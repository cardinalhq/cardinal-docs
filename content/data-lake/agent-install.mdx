# Install with an AI Agent

## What you need

- A Kubernetes cluster running version 1.33 or later, with enough capacity for [Cardinal Data Lake](/data-lake/sizing).
- An AI coding agent you like, configured to deploy to that cluster using `kubectl` and Helm.
- Cloud credentials or API keys that let the agent configure object storage and PostgreSQL. You can use existing
  services or let the agent provision them. Make credentials available through your usual CLI or secret manager.
- A [Cardinal account](https://app.cardinalhq.io) for an [operator-managed install](/data-lake/install), or a license
  file for a [manual Helm POC](/data-lake/manual-install). Use the operator for production.

## What to do

Feed your agent this prompt:

```text copy
Install Cardinal Data Lake on my Kubernetes cluster.
Fetch https://docs.cardinalhq.io/data-lake/agent-install.md and follow it.
Inspect my cluster and available cloud credentials, then prepare the deployment configuration.
Ask me for any missing information and get my approval before creating paid resources or public endpoints.
Verify the installation by sending a test log and querying it back.
When finished, give me the connection details, verification results and upgrade instructions.
```

Include your cluster name, provider and region if your agent does not already know them. The instructions cover AWS,
Google Cloud, OVHcloud and Kubernetes on VPS hosts, including storage, database setup and notifications.

If your agent cannot fetch the URL, open the [install instructions](https://docs.cardinalhq.io/data-lake/agent-install.md)
and copy them into its context. You can also save them as `SKILL.md` for reuse.
